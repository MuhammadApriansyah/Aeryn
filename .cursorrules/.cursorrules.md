## Code Style Rules

### Match Existing Patterns

Before writing any code, **always** check existing patterns in the target directory:

- `aeryn_core/` → Look at sibling modules for structure
- `aeryn_api.py` → Follow existing endpoint patterns
- `dashboard.js` → Follow existing IIFE pattern

### No Test Doubles

**CRITICAL:** Production code must NEVER contain mocks, stubs, or fakes. Use real implementations only.

```python
# WRONG — Never do this
from unittest.mock import Mock
mock_db = Mock()
mock_db.query.return_value = fake_results

# CORRECT — Use real implementation
import sqlite3
conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE ...")
```

### Python Style

- **Formatting:** PEP 8
- **Type hints:** Encouraged for public APIs
- **Line length:** ~100 chars
- **Imports:** Absolute preferred over relative
- **Naming:** `snake_case` for functions/variables, `PascalCase` for classes
- **Virtual environment:** Always use `venv-proot/`

```python
# Good
from aeryn_core.safety.safety_engine import get_safety_engine
from aeryn_core.memory.vault import AerynVault

def get_user_vault(user_id: str) -> AerynVault:
    """Get vault instance for user."""
    vault = AerynVault()
    vault.set_user(user_id)
    return vault

# Bad (relative imports)
from ..memory.vault import AerynVault
```

### JavaScript Style

- **Pattern:** Everything in IIFE `(function() { ... })();`
- **No modules:** No `import`/`export`, no ES6 modules
- **No build step:** Direct browser execution
- **Strict mode:** `'use strict';` at top of IIFE
- **Naming:** `camelCase` for functions/variables, `PascalCase` for constructors

```javascript
(function() {
  'use strict';
  
  var myFeatureData = null;
  
  function loadMyFeature() {
    fetch('/api/v1/my-feature')
      .then(function(r) { return r.json(); })
      .then(function(data) {
        myFeatureData = data;
        renderMyFeature();
      });
  }
  
  function renderMyFeature() {
    var container = document.getElementById('page-content');
    container.innerHTML = '<div class="page"><h1>Feature</h1></div>';
  }
})();
```

## Architecture Rules

### Monolithic Backend + Vanilla SPA

- **Backend:** Single FastAPI app in `aeryn_api.py`
- **Frontend:** Vanilla JS SPA in `dashboard.js`
- **Communication:** REST API + WebSocket
- **No microservices** — everything runs as one API process + one dashboard process

### Database: SQLite Only

```python
# ALWAYS import WAL patch first
import aeryn_core.utils.patch_sqlite  # noqa

# Then use sqlite3 normally
import sqlite3
conn = sqlite3.connect("data/aeryn.db")
```

- **WAL mode:** Enabled automatically via patch
- **busy_timeout:** 5000ms (automatic)
- **Never add PostgreSQL code**

### Process Management: PM2

```bash
# Start all services
pm2 start ecosystem.config.cjs

# Restart after code changes
pm2 restart aeryn-api
pm2 restart aeryn-dashboard

# Check status
pm2 status
pm2 logs aeryn-api
```

### No Frontend Build Step

- Zero npm packages in `apps/web/`
- No webpack, no Babel, no TypeScript
- Files served directly from `apps/web/static/`
- `aeryn-web/` (Next.js) is separate — managed by `ecosystem-web.config.cjs`

## API Endpoint Pattern

When adding new endpoints:

```python
# 1. Import at top of aeryn_api.py
from aeryn_core.<category>.<module> import get_<manager>

# 2. Define Pydantic model (if needed)
class MyRequest(BaseModel):
    field: str = Field(..., description="Description")

# 3. Add endpoint
@app.get("/api/v1/<resource>", tags=["<tag>"])
async def list_resources():
    """List all resources."""
    manager = get_resource_manager()
    return manager.list()

# 4. Add error handling
@app.post("/api/v1/<resource>", tags=["<tag>"])
async def create_resource(data: MyRequest):
    try:
        manager = get_resource_manager()
        result = manager.create(data.field)
        return {"status": "ok", "data": result}
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))
    except Exception as e:
        error("create_resource failed", error=str(e))
        raise HTTPException(status_code=500, detail="Internal error")
```

## SPA Pattern

When adding new pages/features:

```javascript
// 1. Add to navItems
{ id: 'mypage', icon: '📄', label: 'My Page', category: 'work' }

// 2. Add page function
function showMyPage() {
  var container = document.getElementById('page-content');
  container.innerHTML = 
    '<div class="page">' +
      '<h1>My Page</h1>' +
      '<div class="card">' +
        '<p>Content goes here</p>' +
      '</div>' +
    '</div>';
  
  // Load data
  loadMyPageData();
}

// 3. Add data loader
function loadMyPageData() {
  fetch('/api/v1/my-resource')
    .then(function(r) { return r.json(); })
    .then(function(data) {
      // Render data
    })
    .catch(function(err) {
      showErrorBoundary(err.message, err.stack);
    });
}

// 4. Add to router
case 'mypage':
  showMyPage();
  break;
```

## Common Pitfalls to Avoid

1. **Don't add npm packages** — Frontend is vanilla JS only
2. **Don't add PostgreSQL** — SQLite only
3. **Don't use test doubles in production** — Real implementations only
4. **Don't skip WAL patch** — Always import `aeryn_core.utils.patch_sqlite` first
5. **Don't modify ecosystem.config.cjs without testing** — PM2 restart required
6. **Don't add routes that conflict with SPA** — `/plugins` API conflicts with SPA route
7. **Don't forget to activate venv** — `source venv-proot/bin/activate`
8. **Don't ignore file size** — Read large files before modifying
9. **Don't use ES6 modules in frontend** — IIFE pattern only
10. **Don't add relative imports** — Use absolute imports
