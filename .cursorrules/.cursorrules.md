# Cursor IDE Rules for Aeryn Development

## General Principles

1. **Always match existing patterns** — examine how similar code is written before adding new code
2. **Run the full test suite** (`python -m pytest tests/ -x -q`) after every significant change
3. **Zero test doubles in production** — real implementations only, no mocks/stubs/fakes
4. **No TODO comments** — if something needs doing, do it now or create a tracked issue
5. **Update docs** — update README + CHANGELOG + RELEASE before pushing

## Code Style

### Python (aeryn_core/, apps/api/)

- Follow PEP 8 conventions
- Use type hints (`from typing import Optional, List, Dict`)
- snake_case for functions and variables
- PascalCase for classes
- Absolute imports (e.g., `from aeryn_core.memory.vault import AerynVault`)
- Keep functions under 100 lines — split complex logic into smaller helpers
- **First import**: `import aeryn_core.utils.patch_sqlite` (patches SQLite globally)

### JavaScript (apps/web/static/js/)

- No external dependencies — vanilla JS only
- camelCase for functions and variables
- Wrap all DOM operations in `safeExecute()` for error boundary
- Keep state in IIFE scope at top of file
- Use `window.AerynApp` to expose public API
- Follow existing pattern: `render{PageName}()` for page renderers

### CSS (apps/web/static/css/)

- kebab-case for CSS custom properties (`--color-primary`)
- Use `var(--theme-value)` for theme-aware colors
- Support dark/light themes via `[data-theme]` attribute
- Include `prefers-reduced-motion` and `prefers-contrast: high` fallbacks

## Architecture Constraints

1. **Monolithic backend** — FastAPI in single file (`aeryn_api.py`), no separate service per resource
2. **SQLite only** — PostgreSQL errors are expected (system handles gracefully)
3. **No Docker** — native PM2 deployment
4. **Vanilla frontend** — zero JS dependencies, no framework
5. **ARM64** — environment is ARM64 Ubuntu 25.10

## Testing Requirements

- Run `python -m pytest tests/ -x -q` after every change
- **661 tests must pass**
- No `unittest.mock` in `aeryn_core/` or `apps/` directories
- Tests verify real functionality

## Git Workflow

```bash
git add -A
git commit -m "type(scope): concise description"
git push origin main
```

**Commit types**: feat, fix, docs, refactor, test, chore

## Key Commands

```bash
# Activate environment
source venv-proot/bin/activate

# Run tests
python -m pytest tests/ -x -q

# Start server
pm2 start apps/api/aeryn_api.py --name aeryn-api --interpreter ./venv-proot/bin/python

# Restart server
pm2 restart aeryn-api

# Kill port
fuser -k 3010/tcp
```

## Safety Checks

Before completing any task:

1. ✅ All 661 tests pass
2. ✅ No test doubles introduced in production code
3. ✅ README + CHANGELOG + RELEASE updated
4. ✅ Changes pushed to origin/main
